# PhotoArchive

Портативная программа для Windows, которая собирает разрозненные фотографии и видео (с
дисков, карт памяти, скачанных архивов с облачных сервисов и т. п.) в один упорядоченный
архив на локальном компьютере. Распространяется как один исполняемый файл, установка не
требуется.

- Исходные файлы не изменяются, не переименовываются, не перемещаются и не удаляются.
  Программа только читает их и копирует.
- Обработка происходит полностью на локальном компьютере, подключение к интернету не
  требуется.
- Программа бесплатна. Поддержка проекта (донат) добровольна и не связана с доступом к
  функциям.

Этот документ — технический справочник: точные параметры запуска, файл настроек, правила
раскладки файлов. Для пошагового первого запуска — `QUICKSTART.md`, для ответов на
практические вопросы — `FAQ.md`.

## Термины

- **SOURCE** — папка или диск, содержащий исходные файлы фотографий и видео для обработки. В
  графическом мастере обозначается как «Откуда взять фотографии», в текстовых подсказках
  командной строки — «Откуда брать фото».
- **TARGET** — папка, в которую программа записывает результирующий архив. В графическом
  мастере подписывается по выбранному режиму: «Куда сложить архив» (сборка), «Какой архив
  проверить» (пробный прогон), «Где находится архив» (паспорт).
- **WORKDIR** — та же папка, в которой расположен исполняемый файл `PhotoArchive.exe` (не
  соседняя и не вложенная — именно она). Не является ни архивом, ни источником: содержит файл
  `photoarchive_config.yaml`, временный рабочий индекс `work.db` и файл `analyze_report.csv`.
- **Альбом** — папка внутри TARGET (`Albums\<имя>\...`), в которую с сохранением вложенности
  переносится структура папок SOURCE. Противопоставляется раскладке по дате.
- **По дате / dump** — категория файлов, для которых на пути к ним в SOURCE не обнаружено ни
  одной осмысленной (неслужебной) папки; такие файлы размещаются в `ByDate\ГГГГ\...` по дате
  съёмки, а не по исходной структуре папок.
- **RAW-зеркало** — папка `RAW\`, содержащая копии RAW-файлов камеры отдельно от основного
  архива (`Albums`/`ByDate`).
- **Tier** — уровень достоверности определённой даты съёмки файла, от A (наиболее достоверный)
  до D (сигнал отсутствует).
- **Точный дубликат** — файл, содержимое которого (SHA-256) полностью совпадает с уже
  сохранённой в TARGET копией. Повторно не копируется.
- **Near-dup** — файл, визуально похожий на уже сохранённую копию, но не идентичный ей —
  например, кадр из серии последовательных снимков. Сохраняется в архиве всегда, а не
  отбрасывается.
- **Самопоедание** — ситуация, при которой источником для прогона фактически становятся
  файлы, только что записанные этим же прогоном в TARGET (например, при совпадении SOURCE и
  TARGET). Технически исключена — см. [«SOURCE и TARGET: защита от потери
  данных»](#source-и-target-защита-от-потери-данных).
- **DVD-видео-единица** — папка со структурой DVD-Video (`VIDEO_TS`), обрабатываемая как
  единое целое, а не как отдельные файлы.

## Системные требования

- Windows (программа собрана как нативный `.exe`; на других системах может быть запущена
  из исходного кода Python, но это не основной сценарий использования).
- Свободное место на диске TARGET — с запасом, поскольку архив хранит полные копии файлов,
  а не ссылки.
- Учётная запись без прав администратора: программе для обычной работы права
  администратора не требуются.

Программа не устанавливается: файл `PhotoArchive.exe` можно запускать из любой папки, в
том числе с флеш-накопителя. Та же папка, где лежит `PhotoArchive.exe`, — это WORKDIR (см.
[«Термины»](#термины)): в ней появляются рабочие файлы программы (индекс, при необходимости
— файл настроек), не в SOURCE и не в TARGET.

## Запуск

Есть три равнозначных способа запустить программу — они не исключают друг друга.

### Без параметров (меню)

Двойной клик по `PhotoArchive.exe` без каких-либо аргументов командной строки открывает
графический мастер из трёх экранов (в самой программе они подписаны «Шаг 1 из 3» … «Шаг 3
из 3»).

**Экран 1 — выбор действия.** Список из пяти пунктов, каждый — кнопка и краткое описание:

- **Сканирование источника** — посмотреть, что есть в папке с фотографиями. Ничего не
  записывается и не меняется (read-only).
- **Пробный прогон** — проверить, что получится при сборке архива, без реальной записи на
  диск.
- **Сборка архива** — скопировать фотографии в архив и разложить по датам/альбомам.
  Исходные файлы остаются на месте.
- **Паспорт архива** — проверить уже собранный архив и получить отчёт о его состоянии.
- **Выход из программы** — закрыть программу без выполнения каких-либо действий.

Выбор — клик по нужной строке.

**Экран 2 — выбор путей.** Для «Сканирования источника», «Пробного прогона» и «Сборки
архива» нужно выбрать источник фотографий; для «Пробного прогона», «Сборки архива» и
«Паспорта архива» — папку архива. Каждая кнопка открывает стандартное окно выбора папки
Windows. Если для архива выбран корень диска целиком (например, `D:\`), программа сама
использует на нём подпапку `D:\__PhotoArchive__` и пишет об этом пояснением под кнопкой —
отдельного вопроса при этом не задаётся. Выбранный путь показывается на экране полностью.
Кнопка «Далее» ведёт на экран 3 и становится доступной, когда выбраны все пути, нужные для
режима; «Назад» возвращает на экран 1.

**Экран 3 — финальная проверка.** Итог выбора (режим, источник, архив) перед началом работы.
Кнопка «Начать» запускает выполнение, «Назад» возвращает на экран 2 (выбранные там пути при
этом сбрасываются).

Закрыть программу можно в любой момент — крестиком окна на любом из трёх экранов (или
клавишей Escape), либо пунктом «Выход из программы» на экране 1. Во время самой работы
(после «Начать») на экране появляется отдельное окно с ходом выполнения — там программу
можно остановить сочетанием Ctrl+C или тем же крестиком, а клавишей «Пробел» —
приостановить обработку (она остановится после текущего файла) и возобновить нажатием любой
клавиши.

После завершения работы появляется окно «Работа окончена» со счётчиком объектов (найденных —
для сканирования, пробного прогона и паспорта; обработанных — для сборки) и кликабельной
ссылкой на отчёт, открывающейся в браузере по клику. Кнопка «В главное меню» возвращает к
экрану 1 для следующего действия — рабочее окно при этом сворачивается, программа не
закрывается; кнопка «Выход» завершает её.

### Неполная командная строка

Если запустить программу хотя бы с одним аргументом, но без полного набора (например,
только с `--source`, без `--target`), графический мастер не открывается — программа
предполагает, что режим уже выбран через флаги (подкоманда `archive`/`analyze`), и
спрашивает только недостающее (источник и/или архив) текстовыми подсказками в той же
консоли, откуда была запущена.

### Полная командная строка

Если и источник, и архив (для `analyze --target` — только архив) заданы явно через флаги,
программа ничего не спрашивает, не показывает подтверждений и не ждёт нажатия клавиши
перед завершением — это единственный режим, пригодный для запуска из скриптов и
автоматизации.

## Командная строка

```
PhotoArchive.exe archive --source <путь> --target <путь> [--dry-run] [--sample-limit N]
PhotoArchive.exe analyze --source <путь> [--sample-limit N]
PhotoArchive.exe analyze --target <путь>
PhotoArchive.exe --version
PhotoArchive.exe --formats
```

Если подкоманда не указана явно, но задан хотя бы один флаг, поведение соответствует
подкоманде `archive` (сборка) — это поведение по умолчанию.

### Подкоманда `archive` — сборка архива

| Флаг | Назначение |
|---|---|
| `--source <путь>` | SOURCE. Флаг можно указать несколько раз — все SOURCE обрабатываются последовательно за один запуск в один и тот же TARGET. |
| `--source-list <файл>` | Текстовый файл с путями SOURCE, по одному на строку (пустые строки и строки, начинающиеся с `#`, пропускаются). Складывается с `--source`, если указаны оба. |
| `--target <путь>` | TARGET. |
| `--dry-run` | Прогнать все решения (дедуп, определение даты, раскладку) без физического копирования файлов. В отличие от `analyze`, всё же записывает обычные CSV-логи в архив. |
| `--sample-limit N` | Ограничить обработку первыми N файлами источника (для быстрой проверки на малой выборке). |

В качестве `--source` можно также указать `all` — тогда обрабатываются все локальные диски
компьютера (включая диск, на котором расположен TARGET; повторное считывание уже собранного
архива как SOURCE исключено на уровне самой раскладки путей). `all` нельзя сочетать с
другими значениями `--source`/`--source-list` в одном запуске.

### Подкоманда `analyze` — проверка без записи

Работает в двух взаимоисключающих режимах — нужно указать ровно один из `--source`/
`--target`, ни то и другое сразу, ни ни то ни другое:

- `analyze --source <путь>` — быстрая проверка SOURCE по одним лишь метаданным (без
  вычисления хешей — самая медленная часть обработки сознательно пропущена): сколько
  файлов, какого типа, у скольких нет надёжной даты в EXIF, есть ли повреждённые файлы,
  запароленные или подозрительно большие архивы и т. п. Ничего не пишет в TARGET — ни
  файлов, ни логов.
- `analyze --target <путь>` — полная проверка целостности уже собранного архива в TARGET (по
  содержимому — с вычислением хешей): точные и похожие дубликаты, повреждённые файлы, файлы,
  оказавшиеся вне распознанной структуры альбомов, надёжность проставленных дат. Результат —
  файл `passport.html` внутри самого TARGET (единственный побочный эффект на диске; TARGET
  иначе не меняется). Тот же отчёт доступен в меню как пункт «Паспорт архива».

### Общие флаги

- `--version` / `-V` — версия программы и версия используемых бизнес-правил, затем выход.
- `--formats` — список расширений файлов, которые программа распознаёт как фото/видео/RAW/
  архив, затем выход.
- `--help` / `-h` — справка по флагам и подкомандам (можно указать и после конкретной
  подкоманды, например `archive --help`, — тогда справка будет только по её флагам).

Флаг `--sample-limit` считается отдельно для каждого источника, а не суммарно за весь запуск:
при двух `--source` со значением `--sample-limit 200` возможна обработка до 400 файлов.

### Код возврата процесса

| Код | Значение |
|---|---|
| `0` | Успешное завершение. |
| `1` | Неожиданная ошибка программы. |
| `2` | Архив (`TARGET`) уже занят другим одновременно выполняющимся прогоном сборки. |
| `3` | Ошибка конфигурации запуска (например, SOURCE и TARGET указывают на один и тот же путь). |
| `4` | Сборка остановлена из-за нехватки свободного места на диске архива. |
| `130` | Прервано пользователем (Ctrl+C) или закрытием ввода. |

Ненулевой код возврата пригоден для проверки в скриптах автоматизации (`%ERRORLEVEL%`). Код
`1` означает неожиданную программную ошибку — подробности сохраняются в файл `crash.log`
рядом с `PhotoArchive.exe` (не внутри архива), полезно приложить его при сообщении о
проблеме; учтите, что он почти всегда содержит полные пути, включая имя учётной записи
Windows. При нескольких источниках за один запуск итоговый код один на весь запуск: код `4`
(нехватка места) имеет приоритет над остальными, иначе засчитывается первый увиденный
ненулевой код. Подкоманда `analyze` (не пишет в архив) может завершиться только кодом `0`
или `3`. Коды в таблице относятся к запуску из командной строки; при запуске двойным кликом
без параметров выход через «Выход»/крестик/Ctrl+C — это всегда код `0` (работа доведена до
управляемого завершения, а не аварийный обрыв).

## Файл настроек photoarchive_config.yaml

Необязательный файл в той же папке, где лежит `PhotoArchive.exe`. Если его нет, при первом
запуске программа создаёт его сама — полностью закомментированным, со всеми значениями по
умолчанию в виде примеров. Пока строки в нём закомментированы, они ни на что не влияют;
чтобы изменить значение, нужно раскомментировать строку и отредактировать её. Незнакомые
ключи в файле игнорируются, о чём программа сообщает в логе.

SOURCE, TARGET, `--dry-run` и `--sample-limit` через этот файл не задаются — только через
командную строку или интерактивный ввод при запуске.

Полный список настраиваемых ключей, со значениями по умолчанию и пояснением каждого,
находится в файле `photoarchive_config.yaml.example`, поставляемом вместе с программой.
Основные группы настроек:

- **Раскладка по дате**: `bydate_granularity` (`day`/`month`/`year`/`flat` — по каким папкам
  внутри `ByDate` делить недатированные подборки; по умолчанию `month`). Само разделение
  архива на альбомы и раскладку по дате не настраивается — оно фиксировано (см.
  [«Как программа раскладывает файлы»](#как-программа-раскладывает-файлы)).
- **Место съёмки**: `place_lookup` (`offline` — определять город из координат съёмки без
  выхода в интернет, либо `off` — не определять), `home_country` (код страны, при попадании
  в которую в названии папки пишется только город, без страны).
- **RAW**: `mirror_raw` (сохранять ли рядом отдельную копию RAW-файлов, для которых уже есть
  готовый JPEG; по умолчанию — да), `raw_layout` (`mirror` — все RAW-файлы отдельным деревом,
  либо `sibling` — RAW-файл в подпапке рядом с самим снимком).
- **Обход источника**: `scan_system_dirs` (заходить ли в системные папки Windows при
  сканировании целого диска), `default_exclude_dirs`/`extra_exclude_dirs` (список имён
  папок, пропускаемых при обходе), `dump_segment_names`/`extra_dump_segment_names`/
  `dump_segment_prefixes`/`extra_dump_segment_prefixes` (какие имена папок считаются
  «служебными» при выборе — альбом это или нет, см. раздел ниже).
- **Технические пороги**: `max_archive_depth` (вложенность архива в архиве),
  `max_dest_path`, `small_image_px`, `free_space_margin_gb` (резервный запас места на диске
  TARGET — проверяется перед записью каждого отдельного файла: если после записи свободного
  места осталось бы меньше этого значения, прогон останавливается, не дожидаясь полного
  исчерпания места), `read_retry_count`/`read_retry_delay`, `archive_hash_cache`,
  `tmp_extract_dir`, `check_signature` (`false` по умолчанию — проверка сигнатуры файла,
  первых байт содержимого, против расширения в обычном анализе («Сканирование источника»/CLI
  `analyze`); находит переименованные/подменённые файлы, но заметно на медленном/сетевом
  диске, поэтому по умолчанию выключена. «Паспорт архива» проверяет сигнатуру всегда,
  независимо от флага).
- **Диагностика**: `debug` (подробные строки с префиксом `[DEBUG]` в логе `actions.log` —
  причина каждого решения о раскладке/дате, полная трассировка при ошибках. Не ротируется
  отдельно от остальных строк лога: однократно включённый флаг оставит такие строки
  вперемешку с обычными во всех последующих прогонах того же архива, пока флаг не будет
  выключен обратно).

## SOURCE и TARGET: защита от потери данных

Программа жёстко разграничивает права SOURCE и TARGET (см. [«Термины»](#термины)):

- В SOURCE программа никогда не пишет. Ни при каких обстоятельствах она не переименовывает,
  не перемещает, не удаляет и не изменяет файлы или папки в SOURCE — только читает их.
- TARGET пополняется, но не перезаписывается: новый прогон дописывает то, чего там ещё нет,
  но никогда не удаляет и не трогает уже собранное. Каждый прогон программа заново
  определяет, что уже есть в TARGET, читая его фактическое содержимое — отдельного статуса
  «уже обработано» между запусками не хранится.
- Если SOURCE и TARGET после разрешения путей совпадают — запуск сразу отклоняется с
  понятной ошибкой (это самопоедание, см. «Термины»).
- Если SOURCE оказывается вложен внутрь TARGET — запуск также отклоняется: иначе программа
  рисковала бы читать как «новые» файлы, которые сама только что туда записала.
- Обратная ситуация — TARGET вложен внутрь SOURCE (например, архив собирается прямо на
  диске, который целиком же и сканируется) — поддерживается: при обходе SOURCE программа
  сама пропускает собственную папку TARGET, не спускаясь внутрь.
- Если путь к TARGET похож на подпапку уже существующего где-то ещё архива (то есть у одной
  из родительских папок уже есть служебная структура), программа предупреждает об этом в
  логе — вложенность одного архива в другой не запрещена технически, но обычно означает
  ошибку выбора пути.
- Во время реальной записи в TARGET программа удерживает файл-блокировку на время работы —
  второй одновременный запуск сборки в тот же TARGET сразу останавливается с понятной
  ошибкой, вместо того чтобы конкурировать за одни и те же файлы. Работа в режиме чтения
  (сканирование, пробный прогон, проверка архива) блокировки не требует и может выполняться
  параллельно.

## Как программа раскладывает файлы

### Дедупликация

В начале каждого прогона программа индексирует фактическое содержимое архива (папки
`Albums`, `ByDate`, `RAW`) — это и есть единственный источник истины о том, что уже собрано.
Служебные папки, папка со спорными файлами и недатированные файлы (см. ниже) в этот индекс
не входят.

- Точное совпадение содержимого (побайтовое) — файл не копируется повторно.
- Похожий, но не идентичный файл (например, тот же кадр с другим уровнем сжатия, или
  соседний кадр серийной съёмки) — не отбрасывается: если новый экземпляр заметно лучше по
  качеству (больше пикселей, есть данные камеры и т. п.), он дописывается рядом с исходным
  под тем же именем с числовым суффиксом; если явно не лучше — всё равно дописывается как
  отдельная копия. Файл, который может оказаться самостоятельным кадром, программа никогда
  не отбрасывает молча ради экономии места.
- Внутри одного и того же альбома дубль (в том числе совпадающий по имени и содержимому)
  пропускается, а факт пропуска записывается в текстовый файл `__ПРОПУЩЕННЫЕ_ДУБЛИ.txt`
  прямо в папке этого альбома.

### Определение даты

Для каждого файла программа собирает доказательства даты съёмки из нескольких источников
и присваивает степень доверия («тир»):

1. **Высокая точность (тир A)** — дата из EXIF/метаданных камеры (в том числе у видео), либо
   дата из парного RAW-файла, если у самого JPEG метаданных нет.
2. **Средняя точность (тир B)** — дата, зашитая в самом имени файла по распознаваемому
   шаблону (например, `IMG_20190715_120000.jpg`) или в имени папки-источника (например, папка
   «Отпуск 2015» задаёт хотя бы год).
3. **Низкая точность (тир C)** — оценка по соседним файлам той же папки с надёжной датой
   (медиана дат, интерполяция по номеру кадра) либо по времени изменения файла, если оно не
   похоже на массовое копирование (например, если у десятков файлов подряд одна и та же
   минута — это, скорее всего, момент копирования, а не съёмки, такая метка в расчёт не
   идёт).
4. **Нет данных (тир D)** — файл всё равно сохраняется в архиве, но помещается в отдельную
   папку для недатированных файлов (см. ниже), а не куда попало.

Даты тиров B и C дополнительно записываются в лог `dates_review.csv` — для тех, кто хочет
проверить их вручную (у тира A проверять нечего, у тира D даты нет вовсе).

### Раскладка: альбом или по дате

Программа всегда сохраняет пользовательские альбомы как есть, а всё остальное раскладывает
по дате съёмки — это фиксированное поведение, отдельной настройкой оно не переключается.
Разложить по дате **весь** источник целиком, минуя поиск альбомов, можно отдельными
приёмами — см. ниже про запись вида `D:` в файле настроек и про переименование папки с
тильдой.

Решение, является ли путь «альбомом», принимается по каждому сегменту пути от корня SOURCE
(включая имя архива, если файл находится внутри `.zip`/`.rar`/`.7z`/`.tar`):
если хотя бы один сегмент пути похож на служебную/автоматическую папку (например, `DCIM`,
`Camera`, `WhatsApp Images`, `Загрузки`, безымянная «Новая папка», или папка, чьё имя
начинается с камеры конкретной модели), файл целиком уходит в раскладку по дате — даже
если глубже по пути встречается папка с осмысленным именем. Если ни один сегмент не
похож на служебный, путь целиком становится альбомом: каждая папка в дереве — это свой
собственный, отдельный альбом, вложенный в родительскую (например, «Море» → «Отпуск 2015»
дают два раздельных альбома `Отпуск 2015` и `Отпуск 2015\Море`, а не общую папку с двумя
подпапками).

Список «служебных» имён и то, начало ли имени сравнивается или имя целиком, можно
редактировать через ключи `dump_segment_names`/`dump_segment_prefixes` (и их `extra_`-
дополнения) в файле настроек. Есть также способ вручную заставить программу считать
конкретную папку-источник «служебной» независимо от списка — переименовать её так, чтобы
имя начиналось с тильды (`~МояПапка`); сама программа исходные папки никогда не
переименовывает — это ручной сигнал со стороны пользователя.

Если нужно разложить по дате вообще **весь** диск целиком (например, `D:`), не переименовывая и
не перечисляя каждую папку верхнего уровня по отдельности — в `extra_dump_segment_names`
файла настроек можно добавить запись вида `D:` (буква диска и двоеточие, без обратного
слэша). Это не имя папки (реальная папка не может называться буквально «D:» — двоеточие
запрещено Windows в именах файлов и папок), а отдельная команда «этот источник целиком — по
дате»: поиск альбомов для такого источника не выполняется вовсе, как если бы каждая папка на
пути была переименована с тильдой.

Раскладка по дате внутри `ByDate` делится на подпапки по гранулярности из
`bydate_granularity` (по умолчанию — по месяцам), с указанием определённого места
(города) в имени папки, если оно известно.

Если один и тот же файл (по содержимому) одновременно встречается в источнике и в
настоящем альбоме, и в месте, которое разложилось бы по дате, — в архив попадает ровно одна
копия, и она всегда оказывается в альбоме: осмысленные альбомы обрабатываются раньше
служебных папок независимо от того, в каком порядке они физически расположены на диске.
Эта гарантия действует только в пределах одного прогона — если то же содержимое уже осело в
`ByDate` в одном из прошлых пополнений архива, задним числом оно в альбом не переносится
(архив пополняется, а не перезаписывается).

### RAW-файлы

Если у RAW-файла есть парный JPEG (снимок в двух форматах сразу), в основной архив
попадает JPEG, а RAW при включённой настройке `mirror_raw` (по умолчанию — включена)
сохраняется отдельно, в зеркальной структуре или рядом с самим снимком — в зависимости от
`raw_layout`. Если у RAW-файла пары нет, он сохраняется всегда, независимо от `mirror_raw` —
единственный носитель кадра никогда не пропускается молча.

### Зоны доверия и системные папки

При сканировании целого диска программа не заходит по умолчанию в системные папки Windows
(`Program Files`, `Windows`, `ProgramData`, временные и кеш-папки приложений и т. п.) —
это экономит время на заведомо не-фото данных. Если источник указан прицельно внутрь такой
папки, она обрабатывается как обычно — явное указание сильнее автоматического исключения.

Внутри того, что реально обходится, файлы, лежащие в «шумных» местах (кеши браузеров,
временные папки, кеши миниатюр), рассматриваются строже: любое сомнение в том, что файл —
настоящая фотография (маленький размер, отсутствие данных камеры и т. п.), приводит к тому,
что файл просто пропускается с записью в лог, без копирования и без помещения в папку
спорных файлов. В обычных пользовательских папках то же самое сомнение приводит к
противоположному решению: файл сохраняется в архив с пометкой на всякий случай, либо
уходит в папку спорных файлов, если это явно не фотография. Уверенно опознанная
фотография (полноразмерная, с данными камеры) сохраняется всегда, из любого места, включая
системные и «шумные» папки.

### Распаковка вложенных архивов

Архивы (`.zip`/`.rar`/`.7z`/`.tar`/`.tar.gz`/`.tar.bz2`), найденные внутри источника,
распаковываются во временную папку, содержимое обрабатывается как обычные файлы источника,
после чего временная папка сразу очищается перед следующим архивом — одновременно занятое
место на диске не превышает размера одного, самого большого архива. Вложенные архивы
(архив внутри архива) разворачиваются рекурсивно, до глубины `max_archive_depth`.

Перед распаковкой применяется несколько проверок:

- Если ожидаемый распакованный размер (плюс резерв `free_space_margin_gb`) больше, чем
  свободно на диске — архив пропускается. Если размер по оглавлению определить не удаётся —
  архив тоже не распаковывается и считается потенциально опасным, а не оценивается «на
  глаз» по степени сжатия.
- Архив с чрезмерной вложенностью, чрезмерным суммарным объёмом или более чем 200 000
  записей внутри (защита от архива с огромным числом почти пустых файлов, который проходит
  проверку по объёму, но перегружает обработку количеством записей) — пропускается как
  потенциально опасный.
- Запароленные архивы не распаковываются, обработка продолжается со следующим файлом.
- Если оглавление архива содержит запись с попыткой выйти за пределы временной папки при
  распаковке (составной путь с `..` или абсолютный путь) — архив не распаковывается вообще.
- Если внутри распакованного дерева обнаруживается символическая ссылка или junction —
  содержимое архива не читается, это тоже считается потенциально опасным.
- Архив, не содержащий внутри (в том числе во вложенных архивах) ни одного медиафайла, —
  не распаковывается, о чём делается запись в логе.

Происхождение файлов, извлечённых из архива, везде (в логах, в `_Unsorted`, в
`ByDate\0000-undated`) записывается сквозным путём — например, `Фото2015.zip →
2015/Море/IMG_1234.jpg`.

Отдельно от архивов — если при обходе источника попадается папка-ссылка (junction или
symlink), ведущая сама на себя или на одну из уже пройденных родительских папок, такая
папка исключается из обхода, чтобы не уйти в бесконечную рекурсию.

### DVD-видео (VIDEO_TS)

Папка классической структуры DVD-видео (содержащая файлы `.vob`/`.ifo`/`.bup`) обрабатывается
как единое целое, а не как набор отдельных файлов: копируется в архив полностью или не
копируется вовсе, без частичного дописывания. Если такая папка обнаруживается прямо на
подключённом съёмном/оптическом диске, она попадает в альбом, названный по метке этого
диска; иначе — по обычным правилам «альбом или по дате» для места, где она была найдена.

## Структура архива на диске

```
{TARGET}\
├── Albums\                     — пользовательские альбомы, повторяют структуру SOURCE
├── ByDate\                     — всё без альбома, разложено по дате
│   └── 0000-undated\           — файлы без надёжной даты
├── RAW\                        — отдельное RAW-зеркало (если raw_layout=mirror)
├── _Unsorted\                  — спорные/повреждённые/неопознанные файлы
└── __служебные_файлы\          — логи, отчёты, технические файлы (не медиаконтент)
    ├── logs\                   — CSV- и текстовые логи прогонов
    ├── report.html             — отчёт о последней сборке (пробном прогоне, сканировании)
    ├── report_detail.xlsx      — построчная таблица к последнему report.html
    ├── passport.html           — отчёт «Паспорт архива» (если запускался)
    ├── passport_detail.xlsx    — построчная таблица к последнему passport.html
    └── archive_cache.db        — кэш хешей и реестр DVD-единиц (см. «Известные ограничения»)
```

Папка `__служебные_файлы` — это не фотографии и не видео, а рабочие файлы самой программы,
и при следующем прогоне она будет создана заново, если её удалить. Но удалять её без
раздумий не стоит — см. [«Известные ограничения»](#известные-ограничения): по ней программа
узнаёт уже собранный архив, и в ней же хранится кэш хешей уже обработанных файлов.

## Логи и отчёты

После сканирования, пробного прогона, реальной сборки или проверки архива программа
формирует наглядный отчёт `report.html` (или `passport.html` для проверки архива) и
предлагает открыть его в браузере.

Помимо отчёта, при реальной сборке в папке `__служебные_файлы\logs\` ведутся построчные
текстовые и табличные (CSV) логи — что дописано в архив, что пропущено как дубль, какие
файлы оказались спорными, для каких файлов дата определена не по метаданным камеры, какие
файлы не удалось прочитать, и т. п. Каждый из файлов лога при превышении 20 МБ
переименовывается с меткой времени и начинается заново; хранятся не более трёх последних
таких переименованных файлов на каждое имя.

Сам `report.html` (и `passport.html`) содержит только сводные числа и диаграммы; полная
построчная разбивка вынесена в таблицу `.xlsx`, которую открывает кнопка «Детализированный
отчёт» в отчёте. `report_detail.xlsx` — одна строка на файл (или DVD-единицу) прогона, с
исходной папкой, именем, типом медиа, был ли файл скопирован, куда попал и с каким файлом
архива совпал как точный дубликат. `passport_detail.xlsx` — одна строка на находку при
проверке архива (повреждённый файл, дубликат, похожая серия, вложенный запароленный или
нечитаемый архив). Обе таблицы кладутся рядом с самим отчётом, перезаписываются при каждом
запуске и относятся только к этому конкретному прогону, не к истории архива целиком.

Быстрая диагностика источника (`analyze --source`, она же пункт «Сканирование источника»)
дополнительно пишет `analyze_report.csv` в рабочую папку рядом с `PhotoArchive.exe` —
перезаписывается при каждом запуске, в архив не попадает. Сам `report.html` для этого
режима также показывает дерево реальной структуры SOURCE (как файлы фактически лежат на
диске сейчас) — отдельно от предсказанной раскладки по датам/альбомам, описанной ниже.

## Поддерживаемые форматы

Актуальный список (тот же, что печатает `PhotoArchive.exe --formats`):

- **Изображения**: jpg/jpeg, png, heic/heif, tif/tiff, bmp, webp, gif (только статичный —
  анимированный GIF считается не фотографией).
- **RAW**: cr2, cr3, nef, arw, dng.
- **Видео**: mp4, mov, m4v, avi, mkv, 3gp, mts, m2ts, wmv, flv, webm, mod, tod, vob.
- **Архивы** (распаковываются автоматически): zip, rar, 7z, tar, tar.gz/tgz, tar.bz2.

Файлы прочих типов (документы, музыка, исполняемые файлы и т. п.) при обходе источника
просто пропускаются — они вне области применения программы.

## Известные ограничения

- Длина пути к файлу может упираться во внутренние ограничения внешних инструментов
  (распаковки архивов, чтения метаданных) на очень глубоко вложенных источниках — сама
  программа обходит стандартное ограничение Windows на длину пути (260 символов), но
  вызываемые ею внешние утилиты — не всегда.
- Числовые суффиксы у копий (`_1`, `_2` и т. п.) не гарантированно стабильны между полными
  пересборками архива с нуля — они зависят от порядка обхода файлов.
- После смены правил раскладки уже собранные файлы задним числом не пересортировываются
  (архив пополняется, а не перезаписывается) — новые правила касаются только вновь
  дописываемых файлов.
- Проверка целостности по контрольной сумме (SHA-256) требует хотя бы одного полного чтения
  файла с диска — на объёмных видеофайлах (домашняя видеосъёмка, фильмы) это может занимать
  заметное время на файл, а на архиве с большим числом таких файлов — часы суммарно; скорость
  определяется скоростью самого диска, а не программой.
- Пробный прогон и быстрая диагностика источника (`analyze --source`) не сверяются со
  списком уже заархивированных DVD-видео-единиц (см. выше) — такая единица в их предпросмотре
  всегда показывается как новая, даже если фактически уже добавлена в архив. Реальная сборка
  (включая `--dry-run`) определяет повтор корректно.
- **Сетевой путь в формате UNC без буквы диска** (`\\сервер\ресурс\...`) официально не
  поддерживается и не тестировался. Короткие UNC-пути, вероятно, будут работать, но глубоко
  вложенные или длинные — нет, в отличие от локальных длинных путей: внутренний механизм
  защиты от ограничения Windows на 260 символов пути (`winlong()`) — расширение пути до формы
  `\\?\...` — сознательно не применяется для UNC (нужна другая форма префикса, `\\?\UNC\...`,
  отдельно не реализована).
- **Буква сетевого диска, подключённая через «Подключить сетевой диск»** (например, `Z:\Фото`)
  обрабатывается так же, как локальный диск, и ожидается её корректная работа — но это не
  подтверждено на реальном сетевом ресурсе (скорость и устойчивость к разрывам соединения —
  отдельный вопрос, независимый от корректности обработки путей).
- Если SOURCE и TARGET указаны разными буквами сетевых дисков, которые на сервере физически
  ссылаются на пересекающиеся области (например, буква TARGET подключена к подпапке того же
  сетевого ресурса, к которому подключена буква SOURCE) — программа не обнаружит это
  пересечение сама (`os.path.realpath()` не резолвит букву сетевого диска до общего сетевого
  пути). Последствия некритичны: уже записанные в TARGET файлы, повторно обнаруженные при
  обходе SOURCE, дедуп по содержимому распознает как точные дубликаты и не скопирует повторно
  — потери данных не происходит, только впустую потраченное время на повторное чтение.
  Рекомендуется не создавать такие вложенные сетевые подключения одновременно для SOURCE и
  TARGET.
- **Папку `__служебные_файлы\` внутри TARGET нельзя переименовывать или удалять не
  задумываясь.**
  Это основной признак, по которому программа опознаёт уже собранный архив (запасной, менее
  надёжный — одновременное наличие папок `Albums\` и `ByDate\`); её удаление не портит сами
  фотографии и видео, но: программа перестанет с одного взгляда узнавать архив как уже
  существующий (упадёт на запасной признак, если он есть, иначе предложит собрать заново поверх
  тех же файлов), а кэш хешей уже обработанных файлов (`archive_cache.db` внутри этой же папки)
  будет потерян — следующий прогон пересчитает хеши всего архива заново с нуля, что на большом
  архиве заметно медленнее обычного пополнения. Тот же файл хранит и реестр уже заархивированных
  DVD-видео-единиц (см. [«DVD-видео (VIDEO_TS)»](#dvd-видео-video_ts)) — его потеря не просто
  замедляет, а приводит к реальному повторному копированию уже архивированных DVD-дисков при
  следующем сканировании того же источника, под новым именем (`VIDEO_TS (2)`), не только к
  лишнему времени на пересчёт.
- **Не отключайте TARGET физически (не по «безопасному извлечению устройств») во время работы
  программы.** Это особенность кэша записи Windows, а не программы: файл может быть показан в
  логе как успешно сохранённый, но физически ещё не долетевший до диска — при грубом
  отключении такие «уже готовые» файлы могут не сохраниться. Безопасное извлечение устройства
  (или просто дождаться завершения прогона) полностью снимает этот риск.
- **Не рекомендуется указывать в качестве SOURCE/TARGET непроверенный сетевой путь**
  (`\\сервер\ресурс\...`). Это особенность поведения Windows, а не программы: при первом
  обращении к SOURCE (включая простое открытие папки) Windows автоматически выполняет
  NTLM-аутентификацию на указанном сервере текущими учётными данными пользователя. Если сервер
  контролируется третьей стороной (поддельный сетевой ресурс в локальной сети, вредоносная
  ссылка), это может быть использовано для перехвата хеша пароля с последующим офлайн-подбором,
  ещё до начала сканирования файлов. Рекомендуется указывать только пути на доверенных
  серверах/NAS.
